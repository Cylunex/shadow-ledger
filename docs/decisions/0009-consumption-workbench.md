# ADR 0009：可信消费工作台、来源观察与建议反馈

## 状态

已接受，2026-09-04。用户批准实施消费闭环优化方案。

## 决策

- 保留 LedgerRecord 唯一事实状态、原 ID、URI、MoneyEntry 最终金额及 Asset/Identity 边界。
- CaptureSource 初始原文不覆盖。SourceObservation 保存追加的来源观察、内容哈希、解析版本及字段
  定位；同观察版本不同内容冲突。来源变化只进入用户复核，不覆盖已确认事实。
- 用户可明确保留原事实、采用候选修正同一记录，或关联额外证据。采用候选必须检查记录与观察版本，
  在同一事务保存决定、事实修改与审计；不允许用观察入口改变记录种类或绕过确认权限。
- 待处理工作台是既有草稿、导入复核、来源变化、身份建议和采集失败的分页投影，不引入第二套事实状态。
- 商家身份和退款关联允许显式保持未知。金额异常需用户核对；来源冲突需先处理。普通规范化缺失不阻塞确认。
- 复购时间与金额分开推断；多行订单不把整单价格分配给商品。单行订单金额明确为包含优惠与运费的整单口径。
  新算法使用独立版本，旧快照仍可验算。启发式 confidence 不呈现为校准概率。
- SuggestionFeedback 按 owner 与事件键保存忽略本次、稍后提醒、已处理，不绑定单次 ForecastRun。
  新一次实际购买、新周期到期、新使用周期构成新的事件；反馈不修改计算快照与哈希。
- 身份合并以用户确认、幂等键、稳定加锁顺序与循环检测保护，不覆盖原名、不删除旧 ID。
- 移动端只增加显式开启、绑定当前用户、可清空且有期限的文本草稿队列；同步只创建草稿。
  不离线确认、不离线保存附件或认证 token，不引入全量离线财务数据库。

## 排除范围

不引入账户、余额、Posting、PaymentAllocation、对账、自动确认、生产本地身份、独立文件存储。
支付宝/微信未提供真实导出时只做严格可检测的已知表头文本适配与合成回归，不能宣称所有版本均兼容。
NAS 发布仍需要独立部署授权及隔离迁移/恢复验收。
