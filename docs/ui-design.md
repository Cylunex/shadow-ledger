# UI 与交互设计

## 1. 体验目标

- 手机单手优先，普通支出在数秒内完成；
- “先记下来”优先于“先整理完整”；
- 自动推断不确定时才要求纠正；
- 金额、消费语义、计划使用相同视觉语言，但明确区分事实与建议；
- 在 Shadow App WebView 与普通现代浏览器中保持一致；
- 不依赖断网离线模式，网络失败时保留当前表单并允许重试。

## 2. 导航

移动端四个主导航：

```text
记录    消费    计划    洞察
```

桌面端使用左侧栏，右上角提供全局搜索、草稿箱和快速记录。二级对象如分类、商家身份、导入
导出和设置放入“更多/设置”，不占主导航。

## 3. 首页 / 记录

```text
┌─────────────────────────────┐
│ 本月概览                     │
│ 支出 / 收入 / 退款 / 净支出   │
├─────────────────────────────┤
│ ¥ 金额                       │
│ 一句话描述（可选）             │
│ [支出] [收入]          [记录] │
├─────────────────────────────┤
│ 说一句  扫截图  复制上次        │
├─────────────────────────────┤
│ 待确认草稿                    │
│ 最近记录                      │
│ 即将到期                      │
└─────────────────────────────┘
```

录入规则：

- 数字键盘自动聚焦，金额允许稍后补充的消费通过“只记内容”入口创建；
- 描述联想最近标题、商家和分类，但不会阻止自由文本；
- 日期、币种、分类、场景和可选支付方式放在展开区；
- 提交后显示轻量预览和撤销入口，不跳到复杂详情页；
- 解析不确定字段显示“建议”标记，不弹出连续确认框。

## 4. 时间线

记录页使用可折叠的“搜索与筛选”面板：状态支持已入账、草稿和已撤销，收支类型支持支出、
收入和退款；更多筛选包括全文搜索、日期范围、分类、场景、支付方式和金额范围。应用中的筛选数量会
显示在面板标题旁，“重置”恢复默认已入账时间线。时间线使用 cursor 分页并通过“加载更多”
继续追加，切换草稿箱时保留其他筛选条件。

每条记录展示：

```text
主要标题 / 原始商家                 金额或“金额未知”
场景 · 分类 · 时间
主要内容 chips
草稿 / 已撤销 / 有附件 / 待核对 标记
```

确认事实、草稿和预测不得只靠颜色区分；必须同时有文字或图标。时间线默认不显示 voided，用户
可以在筛选中打开。

## 5. Record 详情

按重要性组织：

1. 状态、最终金额、时间、标题和支付方式（未知显示未提供）；
2. 消费场景、商家、渠道、地点和评价；
3. 主要内容、数量单位和明细备注；
4. 小票/截图和其他来源；
5. Health/Travel 等关联；
6. 原始识别文本和审计信息（折叠）；
7. 修正、退款、复制、转为周期、撤销。

用户编辑规范身份时，原始文本只读展示，避免误以为修改 Merchant 会改写订单证据。

## 6. 草稿确认

草稿只突出需要决策的内容：

```text
总金额                 必查
收入/支出/退款          必查
时间                   建议核对
主要内容                建议核对
分类、场景、商家         自动推断，可展开修正
复杂原始明细             默认折叠
```

批量导入提供“全部确认”前的异常摘要：金额缺失、疑似重复、日期异常和低置信度字段。不能要求
用户逐条检查所有正常记录。

导入后“导入复核”工作台只显示需要人工决定的重复、退款对应、金额异常和待确认商家。卡片同时
展示不可覆盖的原始商家/商品文本；确认规范商家时可以选择生成精确匹配规则，并明确规则可撤销。
正常且已有活动规则的导入项自动离开待复核队列，但仍保留机器可读的复核记录。

草稿卡片直接提示“编辑、确认、删除”并可进入详情执行对应操作；删除只用于未确认草稿。
已入账卡片提示“查看、撤销”，详情中的撤销会说明记录将退出统计且不做物理删除。草稿箱顶部
提供“确认这批”，只汇总当前筛选条件命中的草稿，并展示支出、收入、退款和金额未知的数量
摘要。批量操作最多处理 1000 条，版本冲突时明确提示整批未入账。

## 7. 消费页

首页卡片：外卖、堂食、饮料、购物、服务、交通、娱乐、旅行。下方展示：

- 常去商家；
- 常买/常点内容；
- 最近评价偏低但重复购买的内容；
- 待确认身份合并。

Merchant/Item 详情展示原始别名、消费次数、最近时间、金额范围、评价和关联记录。不展示库存
剩余量。

## 8. 计划页

分为四个视图：

```text
想要：想买、想吃、想去、考虑取消
周期：订阅、会员、固定事项
提醒：即将到期、已到期、已忽略
使用周期：用户明确开始、预计结束和实际结束的消耗品使用
```

洞察页可按需计算持久化 Forecast，但它仍是可删除、可重算的建议缓存。所有提示使用“可能、预计、
建议”措辞，展示算法版本、可信度和解释，不以已发生事实的视觉样式呈现。

月度消费目标放在洞察页内，只允许设置总额或分类目标。界面不出现“可用余额”、资金结转或
信封账户等传统预算概念。

## 9. 洞察页

首版图表控制在：

- 月度收入、支出、退款和净支出；
- 分类金额趋势；
- 月度总额与分类目标进度，以及未计入进度的未知金额记录；
- 消费场景次数；
- 常去商家与常买内容；
- 平均消费间隔。

每张图都显示时间范围、币种和样本数。金额未知的消费参与频率统计但不参与金额统计。退款单独
展示，净支出同时给出计算说明。

## 10. 搜索

全局搜索覆盖标题、原始商家/渠道、Merchant、Item、明细原名和备注。结果按 Record、商家、
内容、计划分组。搜索不将 CaptureSource.raw_payload 的全部原文放入默认索引，避免隐私扩大；
原始文本只在来源详情中查看。

## 11. 空态与错误

- 首次使用：展示金额快速记录和截图入口，不展示空图表墙；
- 无金额消费：明确说明仍会参与频率和偏好统计；
- 解析失败：保留附件，给出重试和手工创建按钮；
- 上游不可用：本地事实可继续保存，关联显示“稍后同步”；
- 网络错误：保留表单，使用相同 Idempotency-Key 重试；
- 版本冲突：显示服务端最新值和当前改动，不静默覆盖。

## 12. 可访问性与性能

- 触控目标至少 44×44 CSS px；
- 支持系统字号、深色模式、键盘导航和 reduced motion；
- 文本与背景满足 WCAG AA；
- 首屏不等待洞察聚合和外部服务；
- 时间线 cursor 分页，图片使用 Asset 缩略图和懒加载；
- 图表同时提供文本摘要；
- 服务端渲染主要页面，渐进增强失败时仍可完成核心录入。
