# 消费闭环优化：实现与验收

版本：1.2.0，决策见 [ADR 0009](decisions/0009-consumption-workbench.md)。沿用 Record 聚合，
不引入账户、余额、复式分录、支付分摊、自动确认或新的身份／文件服务。

## 用户操作

- 记录：显式“确认录入／保存草稿”；状态、关键词、日期、类型、分类、场景、支付方式、金额
  筛选保存在 URL。批量确认只处理勾选项，展示准确数量与分币种、分收支类型金额。
- 待处理：草稿、导入复核、来源变化、身份建议、采集失败共用分页入口；不增加第二套事实状态。
  可直接“复核并确认录入”，也可仅保存决定。商家未知、退款未关联是有效选择。
- 证据：记录详情展示原文、字段定位、来源版本、关联退款与修正审计。退款候选展示商家、
  标题、日期、订单标识等匹配原因，支持部分退款和累计超额提醒，不自动关联。
- 来源变化：只追加观察。用户保留原记录，或填写原因后将候选应用到同一记录；
  同时检查记录／观察版本，不自动确认。多候选无法一一定位时不提供自动应用。
- 多来源去重：选择目标消费关联证据，只有明确勾选才删除重复草稿，金额不相加。
  有附件、退款、使用周期、规划或 Archive 等业务引用时拒绝删除。
- 消费记忆：商家／商品目录、规格、人工身份关联、合并预览、同名候选接受／拒绝、
  历次记录和显式开始／结束使用。旧 ID 保留重定向；复杂合并没有无条件一键撤销。
- 计划与洞察：想要／周期事项创建、编辑、生成草稿；周期暂停／结束不表示已付款。
  建议支持恢复、忽略、稍后、已处理以及按状态回看。复购回看比较截止日前样本与窗口内后续记录，
  不伪称还原当时账本或得到校准准确率。
- 移动端：响应式复核、支持浏览器的安装／分享入口、文本分享预填；只展示文本，不访问其中 URL。
  没有全站 Service Worker 缓存，离线重新打开网页不保证可用。

## 可信度与生命周期

### 金额、确认和反馈

MoneyEntry.amount 仍是 Decimal 最终金额。deterministic-v2 分开推断复购频率与金额：
多行订单（包括未识别身份的行）只提供时间样本，金额未知；单行样本标注为整单金额，不是商品单价。
收入和退款不进入购买间隔样本。证据包含样本数、金额样本数、间隔范围；启发式 confidence
不显示成发生概率。v1 快照按旧结构继续验算，不重写旧哈希。

SuggestionFeedback 唯一键为 owner + episode_key。复购以最后一次实际购买为锚，周期事项以
到期事件为锚，使用结束以使用周期 ID 为锚。运行日期变更不使忽略复活；新购买／新到期／新使用周期
可以形成新建议。稍后到期后恢复 active，反馈版本保留。MCP 建议列表遵循有效反馈状态，但不增加
反馈写工具或原始证据读取工具。

单条／批量确认、复核并确认、来源采用候选均使用事务。金额异常未核对、关联来源有 pending
观察时阻止直接确认；普通身份缺失不阻止确认。版本冲突返回 409，表单不清空，提供重新读取入口。
已确认记录通过撤销退出统计，不物理删除。

### 来源数据

CaptureSource 保存初始原文。SourceObservation 追加外部版本、内容哈希、payload、candidate、
parser/version、schema_version、field_evidence；仅复核状态、resolution、revision 可变。
同版本不同内容／解析结果返回 409。旧来源再次接入时补 baseline；新增行号定位不使未改变的旧数据
变成变化观察，也不改变旧的无订单号指纹。

导入、文本采集、Webhook／目录 intake、OCR 复用复核原因服务。OCR 先验证全部候选，再以同一事务
写草稿和来源关联；已有事实重新解析只追加观察。文件仍归 Asset。来源观察、反馈纳入 JSON 导出；
完整恢复仍使用数据库备份。

删除草稿清理来源链接和导入复核项，原始来源／观察保留，并写删除审计。作为商家规则追溯证据的
草稿不直接删除。已删除来源重复投递返回明确冲突，不因网络重试重新生成消费。

### 导入支持范围

四平台原有 Markdown 行为保留，增加原表行／列定位及回归。支付宝／微信是已知表头文本适配，
不是所有官方导出版本的兼容承诺：

| 来源 | 必须识别的列 | 口径 |
| --- | --- | --- |
| 支付宝 | 交易时间、交易对方、商品说明、收/支、金额、交易状态、交易订单号 | CNY；明确收入退款才记 refund |
| 微信 | 交易时间、交易类型、交易对方、商品、收/支、金额(元)、当前状态、交易单号 | CNY；显式商户消费／退款 |

CSV 支持 BOM、表头前说明区；浏览器严格 UTF-8 解码失败后尝试 GB18030。Markdown 也可检测。
订单号始终是字符串，日期为 Asia/Shanghai。金额仅接受明确人民币数值，可有千分位，不从未知币种
字符串提取数字。不创建转账、红包、充值、提现、理财、还款事实。未知状态说明跳过；
非法金额／日期报行号并拒绝整批。仅支持文本，不直接解析任意 XLS/XLSX。

支付宝／微信只有合成样本，真实导出格式和退款口径仍须用户样本验收；测试不复制或提交私人账单。
不新增 OCR 模型、云供应商或默认上传授权。

## 工程实现

- 前端拆为 core、records、workbench、consumption、planning、insights、offline、mobile。
  API client 保持同源 Session/CSRF；重复请求合并，网络／服务端失败重试保留幂等键。
  金额显示与选中合计使用字符串／BigInt，不经浮点求和。
- 新工作台路由封装用户会话边界；应用服务承接复核、身份、观察、反馈和匹配。
  保留原 URL，渐进模块化，不一次换 SPA 或重写全部 API。
- PostgreSQL 版本化写入加行锁，同幂等键／同来源首次创建使用事务级 advisory lock，唯一约束兜底。
  批量记录、合并身份使用稳定 ID 加锁顺序。
- 用户证据接口拒绝 service actor；身份编辑／别名／合并、建议接受／拒绝需 Idempotency-Key。
  观察使用外部版本幂等；反馈使用 item revision + feedback_revision。
- HTML/API 使用 no-store，静态模块要求重新验证缓存。旧 dismiss 桥接新反馈，不扩大旧客户端权限。

### 可选本机队列

用户主动开启；仅保存当前用户快速文本草稿，最多 50 条、7 天有效，可同步／清空。
切换用户会清理，过期数据在下次读取／初始化清理。保存客户端幂等 ID，不存 Cookie、OIDC token、
附件或整份账单。同步前重新检查用户，逐条成功才移除，始终 confirm=false。
浏览器清除数据或禁用存储会影响暂存；不是备份或跨设备同步服务，共享设备不建议使用。

确认／反向合并／同来源导入，以及空库到 0006 再升级 0007、历史忽略回填。
SQLite 只用于快速回归，不代表生产锁语义。

隔离 PostgreSQL 107 通过；Node 前端逻辑 4 通过；Ruff 与 diff 空白检查通过。

NAS 架构／资源／备份告警。发布前按 [operations.md](operations.md) 验收。
